# Сайт-генератор резюме без опыта работы

Сайт для тех, кто ищет первую работу (школьники, студенты, выпускники колледжей/вузов, гэп-год) и не знает, что писать в резюме без опыта. Помогает найти "скрытые" навыки в хобби/интересах и объясняет, где они пригодятся.

## Статус

Прототипная стадия. Все файлы ниже — рабочие черновики для оценки тона, механик и дизайна, не production-код.

**Куда смотреть в первую очередь:** `START_HERE.md` — краткий вход для новой сессии/устройства
(как запустить, карта проекта, текущая точка останова). Здесь — полный журнал решений и
роадмап; деплой — в `docs/DEPLOY.md`.

**Astro-версия собрана (пункт 2 плана «Дальнейшие шаги» → см. конец README).** Теперь в репозитории
две плоскости:
- Ветка/репо на GitHub: **github.com/Splendor1980/resume-site-v17** (пуб/приват — как создано). Это
  git-ремот для синхронизации проекта между устройствами, а не хостинг сайта (см. «Дорожная карта»).
- `index.html` и `data/`, `prototypes/` **в корне** — прежний прототип (SPA на чистом JS), сохранён
  как история решений и для сравнения;
- **Astro-приложение** в `src/` — статические SEO-страницы идей + конструктор как «остров» на
  `/konstruktor/`. Именно его нужно развивать дальше и хостить (шаг 3 плана — домен и хостинг).

**Как запустить Astro-версию локально:**
```
npm install          # первый раз
npm run dev          # http://localhost:4321/  (только один раз потребуется npx playwright install chromium)
npm run build        # статическая сборка в dist/
npm run preview      # посмотреть собранное
npm run test:e2e     # headless-проверка конструктора и SEO-страниц (Playwright)
```
Важно: `npm run build` сам копирует `data/ideas.json`, `prototypes/` и `README.md` в `public/`
(скрипт `scripts/sync-data.mjs`) — это runtime-файлы, на которые ссылается конструктор. Если меняешь
`data/ideas.json` — правь только корневой файл, копия в `public/` обновится при сборке.

Архивы для скачивания версионируются по папке (`resume-site-v4`, следующий будет `v5` и
так далее) — не переиспользуем номер версии повторно, чтобы не путать файлы в загрузках.

**Правило версионирования (договорённость с v17):** текущая папка проекта — `resume-site-v17`,
при загрузке на GitHub имя папки/репо НЕ меняем. Каждое следующее крупное изменение — это
переименование папки в `resume-site-v18`, `resume-site-v19` и т.д. (номер +1 от текущего,
не пропуская). Мелкие правки внутри одной версии папку не переименовывают.

## Ключевые решения по ходу разработки

- **Монетизация**: бесплатно — генерация идей и вдохновение; платно (~50₽ или пакетом) —
  скачивание/редактирование. Рассматриваются варианты: пакет вместо разового платежа,
  бесплатный экспорт с watermark, "поделись — получи бесплатно".
- **Экономика ИИ**: основной объём (подбор идей, сборка черновика резюме) работает БЕЗ
  живого вызова ИИ — за счёт заранее подготовленной базы `ideas.json`. Живой ИИ подключается
  только на платном этапе финальной редактуры текста.
- **SEO**: интерактивный конструктор (это, по сути, SPA на JS) поисковики не индексируют.
  Реальный SEO-трафик должен идти через отдельные статические страницы, сгенерированные
  из `ideas.json` (например `/idei/kvadrokopter-pomoshnik-blogera`). Нужен SSG-фреймворк —
  чистый `index.html` для этого не подходит.
- **Переход на Astro сделан (шаг 2 плана).** Маршруты: `/` — SEO-лендинг, `/idei/<id>/` —
  103 статические страницы идей (генерируются из `ideas.json` на сборке), `/konstruktor/` —
  интерактивный конструктор как «остров» (перенесён из `index.html` почти без изменений).
  Подробное дерево — в разделе «Структура». Осознанные решения, принятые при переносе:
  - **Конструктор НЕ переписан на React/Vue** — логика в `Constructor.astro` осталась ванильной,
    проверена Playwright-тестом (запуск `npm run test:e2e`). Нативный скрипт собирается и
    минифицируется Astro-бандлером; это и есть «остров» в смысле Astro — вся остальная часть
    сайта статический HTML.
  - **Слаги — английские id из базы** (`/idei/strategy_games/`), а не транслитерация названий.
    Причина: стабильность и уникальность без ручной разметки 103 записей; транслитерация
    русских названий в слаги — отдельная контентная/техзадача, не сделано.
  - **`ideas.json` живёт в двух местах**: источник истины `data/ideas.json` (из него генерируются
    SEO-страницы на сборке) + рабочая копия `public/data/ideas.json` для runtime-fetch()
    конструктора. Копию обновляет `scripts/sync-data.mjs` при каждом `npm run build` — руками
    ничего не трогаем.
  - **Домен вписан**: `site` в `astro.config.mjs` и `Sitemap:` в `public/robots.txt` =
    **`https://resumegenerator.ru`** (куплен на reg.ru), на него указывают canonical/OG/sitemap.
    Канонический адрес — без `www`; редирект `www` → без `www` делаем на DNS/хостинге (шаг 3).
  - **HTTPS включён и работает** (18.08.2026): сертификат Let's Encrypt выпущен на домен
    (`CN=resumegenerator.ru`, действителен до 16.11.2026), `http://` отдаёт 301 → `https://`,
    каталоги `/`, `/idei/`, `/methodika/`, sitemap/robots проверены по https — 200, live E2E PASS.
    Открывается из РФ (Yandex Cloud), переживает перевыпуск сертификата автоматически.
- **Стек**: выбран **Astro** — статическая генерация страниц под SEO + "острова" интерактивности
  только там, где нужны (конструктор резюме). Astro не привязан к конкретному хостингу.
- **Хостинг — НЕ Vercel**: изначально рассматривался Vercel, но отклонён. Причины: (1) российские
  карты не принимаются для платных тарифов, (2) отдельные сайты на `*.vercel.app` реально
  попадают в реестр Роскомнадзора, (3) есть подтверждённые случаи, когда `.ru`-домен, привязанный
  к Vercel, переставал открываться с мобильного интернета в РФ без VPN. Для сайта на российскую
  аудиторию (и с `.ru`-доменом) это неприемлемый риск.
  Решение: **Yandex Cloud** (Object Storage + Cloud Functions — аналог связки Vercel) либо для
  старта проще — **обычный российский VPS** (Timeweb Cloud, Selectel, Beget) с Node.js,
  отдающим и статику, и вебхук оплаты с одной машины. Оплата хостинга и оплата от пользователей
  (через ЮKassa) в этом случае в одной валюте/юрисдикции — меньше точек отказа.
  GitHub Pages по-прежнему годится только для просмотра статических прототипов (нет
  серверных функций для вебхука оплаты), не для продакшена.
- **Не только лето**: изначально ниша задумывалась как "выпускники + летние подработки",
  но верно расширена до "любой, кому нечего писать в резюме" — зимние каникулы, первая
  работа после колледжа/вуза, гэп-год. Все тексты должны быть сезонно-нейтральными.
- **Актуальность примеров**: конкретные игры/сериалы/тренды быстро устаревают, поэтому в
  схеме `ideas.json` они вынесены в отдельное поле `examples_now`, не смешанное с
  устойчивой логикой (`category`, `skills`, `roles`).
- **Авторское право**: реальные резюме/тексты других людей брать нельзя ни для дизайна
  (лицензии), ни для контента (авторское право + чужие персональные данные). Вместо этого —
  собственная база примеров, сгенерированная с нуля.
- **Адаптивные шаблоны**: короткий текст ("О себе" в одну строку) не должен выглядеть как
  пустой лист А4. Решение — шаблоны на два типа: "компактный" (сайдбар, крупная типографика,
  визуальные элементы для малого объёма контента) и "плотный" (для тех, у кого есть что
  рассказать развёрнуто). Система должна сама подбирать шаблон по объёму заполненного
  контента, а не спрашивать пользователя.
- **AI-провайдер — выбор сделан (YandexGPT Lite), но подключение сознательно отложено**:
  сравнивали GigaChat Business, YandexGPT Lite и агрегатор Ofox.ai — Ofox отклонён (не решает
  вопрос доступа/данных из РФ, просто прокси поверх зарубежных моделей, неясный статус для
  встраивания в клиентский продукт). YandexGPT Lite выигрывает у GigaChat Business по порогу
  входа (не требует юрлица для базового доступа). НО: оба тарифицируются по токенам без
  абонплаты — значит подключать их есть смысл только когда появится реальный трафик.
  Режимы 1 и 2 (карточки, поиск по профессии) не требуют ИИ вообще — работают на чистом
  `ideas.json`. Запускаем их первыми, без ИИ-зависимости и без затрат.
  **Триггер для подключения живого ИИ**: когда появится измеримый сигнал, что люди реально
  доходят до режима 3 и хотят большего, чем дают карточки — не раньше.
  До этого момента режим 3 остаётся локальным помощником-подсказчиком (поиск по ключевым
  словам + словарь синонимов, уже реализовано в `index.html`), без единого платного вызова.
- **Три режима конструктора** (переключаются одной кнопкой на экране):
  1. *Листай и собирай* — базовый режим, карточки идей с фильтром по тегам (уже реализован).
  2. *Навыки под профессию* — обратный режим: пользователь выбирает интересующую роль/профессию,
     система показывает навыки, которые для неё может — но не факт что имеет — обладать; это
     переиндексация того же `ideas.json` по полю `roles`, отдельных данных не требует.
  3. *Помощник-подсказчик* — сейчас бесплатный и локальный: наводящими вопросами и
     ветвлением по темам подбирает идеи из `ideas.json` (поиск по ключевым словам +
     словарь синонимов, без внешнего ИИ). Живой платный ИИ (RAG поверх той же базы) —
     в бэклоге, подключается по указанному выше триггеру.
- **Самозанятость**: подходит для приёма платежей от физлиц (ставка 4% НПД, лимит дохода
  2.4 млн ₽/год). Для приёма оплаты + автофискализации чеков — агрегаторы вроде ЮKassa,
  CloudPayments (сами формируют чек в "Мой налог").
- **`index.html` теперь загружает полную базу через `fetch('data/ideas.json')`**, а не
  захардкоженный список ~20 карточек, как было раньше во всех трёх режимах. Все 103 записи
  теперь видны и в "листай и собирай", и в "навыки под профессию", и в подсказчике.
  Важно: `fetch()` не работает при открытии файла двойным кликом с диска (`file://`) —
  нужен локальный сервер (`python -m http.server`) или реальный хостинг (GitHub Pages и
  выше уже подходят). На этот случай на странице показывается понятное предупреждение
  вместо молчаливой пустой страницы.
- **Резюме-панель увеличена (~в 1.6 раза, 300px → 480px макс.) и стала редактируемой**:
  поля Имя, Целевая роль, Телефон, Email, Образование — обычные `<input>`, значения
  хранятся в отдельном JS-объекте `profile`, который переживает перерисовку шаблона при
  добавлении/удалении идей (проверено headless-тестом в Playwright — значения не теряются).
  Вопрос "платно или бесплатно" по самому редактированию — сознательно не решён, нужно
  обкатать на реальных пользователях сначала.
- **Исправлена ошибка: нельзя было убрать добавленную идею.** Кнопка "Добавить в резюме"
  раньше навсегда переходила в состояние "Добавлено" без возможности отмены — теперь это
  полноценный toggle (`toggleAdded()`), работает одинаково в режиме "листай" и в
  рекомендациях подсказчика. В режиме "навыки под профессию" тоже поправлено: снятие
  галочки с навыка убирает карточку из резюме, только если ни один другой отмеченный

  полем «системный промт» не существует (ни у Алисы/ЯндексGPT, ни у Гигачата, ни у Google).

  держит её дальше. Самый переносимый формат для продукта — текстовый промт (10–20 строк,
  вставляется в любой текстовый чат), голосовой вариант — надстройка «произнеси это первым
  сообщением». Формат зафиксирован; реализация — в шаге 5.

  собеседования с ИИ (ссылки на Гигачат и Алису + текст промта). Решения: минимум

  пузырь»-подсказка после разблокировки (не отдельная страница), воронка — за пост
